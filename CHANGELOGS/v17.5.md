# 17.5.0

从 17.4.1 补齐到与 Python 侧对齐的一批业务模块。所有新模块均为**逐个对照 `bilibili_api/*.py` 移植**，
接口地址一律取自 `src/data/api/*.ts`（即 Python 的 `data/api/*.json`），不新增任何运行时依赖。

## 新增模块

| 模块 | 内容 |
| --- | --- |
| `dynamic` | `BuildDynamic` 链式构建、`send_dynamic`、定时草案、`Dynamic` 类（点赞 / 转发 / 收藏 / 置顶 / 删除 / markdown）、关注动态与动态页 |
| `favorite_list` | 视频 / 专栏 / 课程 / 话题 / 笔记收藏夹的读写、复制、移动、清理 |
| `channel_series` | 合集列表创建 / 删除 / 增删视频 / 订阅、`ChannelSeries` |
| `creative_center` | 数据概览、播放分析、粉丝数据、稿件管理、评论与弹幕管理、章节与改稿历史 |
| `video_uploader` | `upload_cover`、`VideoMeta`、`VideoUploader`（preupload + upos 分片 + 提交）、`VideoEditor`、线路探测、话题与活动 |
| `emoji` | 表情包列表、表情详情、添加表情 |
| `utils/picture` | `Picture`：从 URL / 文件 / 字节构造，上传到 B 站图床；尺寸由文件头解析，不依赖图像库 |

## 补齐

- `Video`：`like`、`pay_coin`、`share`、`triple`、`set_favorite`、`add_tag`、`delete_tag`、`add_to_toview`、`delete_from_toview`、`get_relation`、`has_liked`、`get_pay_coins`、`has_favoured`、`get_detail`、`get_chargers`、`get_video_snapshot`、`get_ai_conclusion`、`is_forbid_note`、`get_private_notes_list`、`get_public_notes_list`、`get_up_mid`
- `User`：`get_channels`、`get_channel_list`、`get_channel_videos_season`、`get_channel_videos_series`
- `Video` 弹幕：`get_danmaku_view`、`get_danmakus`（`.so` protobuf 解析）、`get_special_dms`、`send_danmaku`、`like_danmaku`、`recall_danmaku`、`operate_danmaku`、`get_danmaku_xml`、`get_history_danmaku_index`、`has_liked_danmakus`、`get_danmaku_snapshot`、`DanmakuOperatorType`
- `utils/BytesReader`（protobuf 手工解析器）+ `utils/danmaku`（`Danmaku` / `SpecialDanmaku` / `DmFontSize` / `DmMode`）
- `Api.requestBytes()`：二进制响应（对应 Python 的 `request(byte=True)`）
- `utils/network`：`Api.updateFiles()` + `BiliAPIFile`，multipart 字段名与文件名规则与 Python 的 curl_cffi 行为一致；`BiliAPIFile` 支持内存内容，不必先落盘

## 已知差异

- `Picture.convert_format` / `Picture.resize` 依赖 PIL，未移植，调用会抛明确错误。
- `dynamic.turn_to_article` / `turn_to_opus` 依赖未移植的 article / opus 模块。
- `VideoUploader` 的分区校验改为按需请求 `pre` 接口（Python 用 115KB 的 `video_uploader_meta_pre.json` 本地数据）；upos 线路表内联为常量（TS 仓库无 `video_uploader_lines.json`）。
- `get_danmaku_view` 的折叠弹幕（字段 9）与图文弹幕（字段 12）保留原始字节。
- 真实弹幕响应里出现过「字段号 1 + wire type 0」的变体，`get_danmakus` 改为按 wire type 跳读（Python 版会在这里错位/报错）；正常响应解析结果一致。
- `recall_danmaku` 参数放进 query（Python 对 GET 仍放 body，会被丢弃）。
- 上游 Python 的两处明显 bug 已按正确语义修正：`channel_series.del_channel_series` 少写 `await`、`VideoEditor._change_cover` 把字符串当字典。其余 Python 行为（含已知怪癖）保持原样并在代码注释中标明。
